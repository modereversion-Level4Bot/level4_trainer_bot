# Восстановление и типовые сбои

## Если бот не запускается

Проверьте по шагам:
1. Файл `.env` существует и заполнен.
2. `BOT_TOKEN` указан корректно.
3. При необходимости выполните `python scripts/init_db.py`.
4. Запустите `python scripts/smoke_check.py` и посмотрите текст ошибок.
5. После этого повторите `python run.py`.

## Что проверить в `.env`

Минимум:
- `BOT_TOKEN`
- `DB_PATH`

Дополнительно для production:
- `APP_ENV=production`
- `ADMIN_IDS`
- `BOT_VERSION`
- `GOOGLE_SHEET_ID`
- `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64`

## Что проверить в `DB_PATH`

1. Путь в `DB_PATH` корректен.
2. У процесса есть права на запись в директорию.
3. После `python scripts/init_db.py` файл базы действительно появился.

Если путь неверный, бот может запускаться с ошибками базы или создавать файл не в том месте.

## Что проверить на Railway

1. Все переменные окружения заданы.
2. `DB_PATH` указывает на директорию внутри persistent volume.
3. Start command: `python run.py`.
4. Сервис перезапущен после изменения переменных.

## Если база не создалась

1. Выполните `python scripts/init_db.py` вручную.
2. Проверьте права на каталог базы.
3. Проверьте корректность `DB_PATH`.
4. Если файл поврежден, сделайте резервную копию и инициализируйте базу повторно.

## Если Telegram API временно недоступен

Возможные признаки: `TimedOut`, `NetworkError`, `RetryAfter`, нестабильные ответы Telegram.

Рекомендуемые действия:
1. Подождать 1-5 минут и повторить запуск.
2. Проверить сетевое соединение сервера/локальной машины.
3. Проверить статус Telegram (внешние мониторинги/сообщества).
4. Перезапустить процесс бота.

В проекте используются безопасные обертки из `core/safe_telegram.py`, поэтому сбой по одному запросу не должен останавливать весь бот.
