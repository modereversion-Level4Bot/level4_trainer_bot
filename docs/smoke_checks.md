# Smoke-check: быстрая проверка проекта

## Команды для запуска проверки

1. Установить зависимости:
   - `pip install -r requirements.txt`
2. Инициализировать SQLite:
   - `python scripts/init_db.py`
3. Запустить smoke-check:
   - `python scripts/smoke_check.py`
4. Запустить бота:
   - `python run.py`
5. (Опционально) Проверить Google Sheets:
   - `python scripts/check_google_sheets.py`
6. (Опционально) Импортировать грамматику:
   - `python scripts/import_grammar.py`
7. (Опционально) Импортировать вопросы:
   - `python scripts/import_questions.py`
   - production full-refresh: `APP_ENV=production python scripts/import_questions.py --allow-full-refresh`
   - безопасная проверка без записи: `python scripts/import_questions.py --dry-run`
8. (Опционально) Preload Questions audio (`file_id` cache):
   - `python scripts/preload_question_audio.py`

## Что считается успешным результатом

Для `python scripts/smoke_check.py`:
- обязательно: `OK: DB schema initialized.`
- при заполненном `BOT_TOKEN`: `OK: Application built...`

Для `python run.py`:
- процесс запускается без ошибок импорта и синтаксиса;
- бот принимает команды в Telegram.

## Проверка `/start`

1. Откройте бота в Telegram.
2. Отправьте `/start`.
3. Для нового пользователя ожидается запуск onboarding:
   - экран выбора языка `🇷🇺 Русский / 🇬🇧 English`;
   - шаги выбора часового пояса, советов дня и напоминаний;
   - финальный экран с кнопкой `🚀 Поехали!` / `🚀 Let’s go!`.
4. После завершения onboarding повторите `/start`:
   - бот должен сразу открыть главное меню v1.0.
5. Сообщение пользователя с `/start` должно быть удалено после обработки.

Это подтверждает, что онбординг и маршрутизация `/start` подключены корректно.

## Проверка Grammar UI v1.0

Что проверить:
1. В главном меню отображается `📘 Грамматика / 📘 Grammar`, если в базе есть хотя бы одна тема `topic_type = main`.
2. Нажатие `📘` открывает экран списка тем в основном UI-сообщении.
3. На экране списка main-тем:
   - корректно отображается прогресс (`📈 Прогресс x из n / 📈 Progress x of n`);
   - при количестве страниц > 1 показывается строка `📄 Страница ... / 📄 Page ...`;
   - на странице отображается до 5 тем;
   - для studied main-тем маркер стоит в конце названия: `Present Simple ✅` / `🔁 Present Simple ✅`;
   - extra-темы не получают `✅`-маркер;
   - отображается `Present Simple` (main-тема);
  - отображается кнопка `📎 Дополнительно / 📎 Additional` при наличии extra-тем;
   - кнопка `📎 ...` расположена перед нижней навигацией;
  - нижняя строка содержит compact navigation и, при необходимости, пагинацию:
    - page 1: `🏠` + `▶️`;
    - middle: `◀️` + `🏠` + `▶️`;
    - last: `◀️` + `🏠`.
4. Нажатие на `Present Simple` открывает экран темы:
   - отображается `simple_explanation`;
   - при наличии `details` и `training` в первой строке кнопки: `📖 Подробнее / 📖 Details` + `🎯 Тренировка / 🎯 Training`;
  - если тема первая в списке: вторая строка `📁 Темы / 📁 Topics` + `➡️`, третья строка `🏠`;
  - если тема промежуточная: вторая строка `⬅️` + `📁 Темы / 📁 Topics` + `➡️`, третья строка `🏠`;
  - если тема последняя: вторая строка `⬅️` + `📁 Темы / 📁 Topics`, третья строка `🏠`;
  - если в списке только одна тема: previous/next не показываются, есть строка `📁 Темы / 📁 Topics`, ниже `🏠`;
  - `📁 Темы / 📁 Topics` всегда возвращает в тот список, из которого открыта тема:
     main -> main list, extra -> extra list.
5. Нажатие `📖 Подробнее / 📖 Details` открывает экран детального описания:
  - первая строка: `⬅️ К теме / ⬅️ To topic` (+ `🎯 Тренировка / 🎯 Training`, если у темы есть вопросы);
  - вторая строка: `📁 Темы / 📁 Topics` + `🏠`;
  - для extra-тем `📁 Темы / 📁 Topics` ведет в список дополнительных материалов.
6. Нажатие `🎯 Тренировка / 🎯 Training` запускает тренировку и открывает первый вопрос в основном UI.
7. Нажатие `📎 Дополнительно / 📎 Additional` открывает список extra-тем:
   - отображается `Irregular Verbs`;
   - на странице отображается до 5 тем;
  - первая нижняя строка: `⬅️ К грамматике / ⬅️ To Grammar`;
  - вторая нижняя строка (пагинация + home):
    - page 1: `🏠` + `▶️`;
    - middle: `◀️` + `🏠` + `▶️`;
    - last: `◀️` + `🏠`.
8. Нажатие extra-темы открывает экран темы; кнопка `📁 Темы / 📁 Topics` возвращает обратно к extra-списку.
9. Previous/next на карточке темы корректно обновляют page context:
   - main #5 (page 1) -> `➡️` открывает main #6 (page 2);
   - main #6 (page 2) -> `⬅️` открывает main #5 (page 1);
   - для extra действуют те же правила.
10. Extra-темы не входят в основной прогресс grammar (`grammar_total` в main menu считает только `topic_type = main`).
11. В EN-режиме все экраны/кнопки локализованы, пустые EN-поля используют RU fallback.
12. Все переходы происходят через редактирование одного main UI-сообщения, без лишних сообщений в чат.

## Проверка Grammar training v1.0

Что проверить:
1. Старт тренировки с карточки темы открывает экран вопроса `1 из N / 1 of N` в основном UI.
2. Ограничение по количеству вопросов работает:
   - если у темы 2 вопроса -> тренировка на 2 вопроса;
   - если у темы 12 вопросов -> в тренировку попадает максимум 10.
3. Вопросы выбираются случайно из темы (до 10):
   - внутри одной тренировки `question_number` не повторяется;
   - порядок вопросов внутри тренировки случайный и фиксируется в session;
   - при повторном запуске тренировки набор вопросов может отличаться.
4. Для текущего полного контента:
   - main-темы: `15` (пагинация `3` страницы по `5` тем);
   - extra-темы: `6` (пагинация `2` страницы: `5 + 1`);
   - вопросов в `grammar_questions`: `1500`.
5. На экране вопроса показываются 3 варианта ответа и кнопки:
   - варианты ответов идут в одной строке: `[answer_1] [answer_2] [answer_3]`;
   - варианты ответов без префиксов `1️⃣/2️⃣/3️⃣`;
  - `⬅️ К теме / ⬅️ To topic`;
  - `🏠`.
6. `correct_answer` в контенте использует только значения `1`, `2`, `3`.
7. Под текстом вопроса всегда добавляется инструкция:
   - RU: `Выберите правильный ответ:`;
   - EN: `Choose the correct answer:`.
8. При правильном ответе показывается toast (не modal popup):
   - RU: `✅ Правильно!`;
   - EN: `✅ Correct!`.
9. При неправильном ответе показывается modal popup (`show_alert=True`) с `wrong_explanation` на новой строке:
   - RU:
     `❌ Неверно!`
     `<пустая строка>`
     `<wrong_explanation_ru>`
   - EN:
     `❌ Incorrect!`
     `<пустая строка>`
     `<wrong_explanation_en или RU fallback>`.
10. После ответа бот сразу редактирует основное UI-сообщение на следующий вопрос (без отдельной кнопки `Далее`).
11. После последнего вопроса открывается экран результата:
   - `excellent` при `wrong = 0`;
   - `good` при `wrong < total / 2`;
   - `weak` при `wrong >= total / 2`.
12. В тексте результата после `Результат:` / `Result:` есть пустая строка.
13. В тексте результата не показывается `из total / of total`:
   - `✅ Правильных ответов: <b>8</b>`;
   - `✅ Correct answers: <b>8</b>`.
14. Для `excellent/good` main-тема помечается как изученная:
   - в списке тем маркер `✅` добавляется в конец названия;
   - прогресс grammar обновляется (`📈 Прогресс x из n / 📈 Progress x of n`);
   - прогресс grammar в main menu тоже обновляется.
15. Для `weak` main-тема не получает новую отметку studied.
16. Если тема уже была studied, повторная тренировка с `weak` не снимает studied-статус.
17. Для extra-тем тренировка работает, но основной progress grammar/main menu не изменяется.
18. Кнопки результата для `excellent/good`:
  - если следующая тема есть: строка 1 `🔂 Повторить / 🔂 Repeat` + `Следующая ➡️ / Next ➡️`;
   - если следующей темы нет: строка 1 только `🔂 Повторить / 🔂 Repeat`;
  - строка 2: `📁 Темы / 📁 Topics` + `🏠`.
19. Кнопки результата для `weak`:
  - строка 1: `📕 Изучить / 📕 Review` + `🔂 Повторить / 🔂 Repeat`;
  - строка 2: `📁 Темы / 📁 Topics` + `🏠`.
20. `📁 Темы / 📁 Topics` на карточках темы, details и result всегда возвращает в текущий список (main или extra), сохраняя page/source_page.
21. RU/EN тексты тренировки корректны; если `wrong_explanation_en` пустой, popup использует RU fallback.
22. Для устаревшей сессии или недоступного вопроса показывается alert, без traceback:
   - `Тренировка устарела... / The training session has expired...`;
   - `Вопрос недоступен. / Question is unavailable.`
23. Все экраны тренировки работают через одно main UI-сообщение, без лишних сообщений в чат.

## Проверка Questions UI v1.0

Что проверить:
1. Из главного меню `🎙 Вопросы / 🎙 Questions` открывает экран выбора уровней (не TODO-alert).
2. Экран выбора уровней:
   - показывает `4️⃣ Level 4`, если есть активные вопросы уровня 4;
   - показывает `5️⃣ Level 5`, если есть активные вопросы уровня 5;
   - содержит compact кнопку `🏠`.
3. Если активных вопросов нет, открывается empty screen:
   - RU: `Раздел пока готовится...`;
   - EN: `This section is being prepared...`;
   - есть только кнопка `🏠`.
4. При повторном входе в started (но не completed) уровень открывается экран `🔄 Start over / ▶️ Continue`.
5. При повторном входе в fully completed уровень открывается отдельный completed re-entry экран `⬅️ / 🔄 Take again` (без `Start over / Continue`).
6. `▶️ Continue` открывает `current_question_number` или первый незавершённый/первый вопрос.
7. `🔄 Start over` открывает первый вопрос уровня и не сбрасывает completed progress.
8. `🔄 Take again` на completed re-entry экране открывает первый вопрос уровня и не сбрасывает completed progress.
9. Базовый экран вопроса:
   - заголовок `Level X — Question N of T` / `Вопрос N из T`;
   - сначала идёт инструкция (`Listen...` / `Прослушайте...`), затем блок `Question` / `Вопрос`;
   - RU label: `Вопрос:`;
   - EN label: `Question:`;
   - `question_en` всегда на английском;
   - вместо отдельных контент-кнопок используется единая `📚 Question review / 📚 Разбор вопроса`;
   - RU: `📚 Разбор вопроса` показывается, если есть хотя бы один review-блок: `question_translation_ru` или `sample_answer_en` или `sample_answer_translation_ru`;
   - EN: `📚 Question review` показывается только если есть `sample_answer_en`;
   - навигация корректна для first/middle/last.
10. Временное аудио:
   - для вопросов с валидным `audio_file` и готовым `media_assets.file_id` отправляется отдельное audio-сообщение;
   - runtime отправляет аудио только по Telegram `file_id` (локальный upload в user chat не используется);
   - при переходе на другой вопрос старое временное аудио удаляется (если возможно);
   - при переходе в уровни/главное меню/completion старое аудио удаляется;
   - source of truth `file_id` cache: `media_assets` (`feature="questions"`, `content_type="question_audio"`, `content_key="questions:{level}:{question_number}"`, `status="ready"`);
   - source of truth временного audio: `temporary_messages` (`feature="questions"`, `message_type="audio"`);
   - review-screen не пересылает audio заново;
   - `🎧 To question / 🎧 К вопросу` не спамит audio повторной отправкой;
   - если `file_id` не готов (нет asset/статус не `ready`/пустой `file_id`), бот не падает и показывает текстовый вопрос.
11. `📚 Question review / 📚 Разбор вопроса` открывает review-screen в том же main UI message.
12. Review-screen показывает все доступные дополнительные блоки сразу в фиксированном порядке:
   - RU: `Вопрос`, `Перевод вопроса` (если есть), `Пример ответа` (если есть), `Перевод ответа` (если есть);
   - EN: только `Question`, `Sample answer` (если есть).
   - EN review не показывает `Question translation` и `Answer translation`.
13. Review-screen не показывает пустые блоки.
14. На review-screen есть кнопка `🎧 To question / 🎧 К вопросу` и обычный navigation row.
15. `📚 Review` не увеличивает progress.
16. `🎧 To question / 🎧 К вопросу` возвращает к base question и не увеличивает progress.
17. `Previous/Next/Finish` из review работают штатно и сбрасывают view к base на целевом вопросе.
18. `⬅️`:
    - открывает предыдущий вопрос;
    - не увеличивает completed progress.
19. `➡️`:
    - помечает текущий вопрос как completed;
    - открывает следующий вопрос.
20. `✅ Finish`:
    - помечает текущий вопрос как completed;
    - открывает экран завершения уровня.
21. Навигационный ряд вопросов (base + review):
   - first: `[🏠] [➡️]`;
   - middle: `[⬅️] [🏠] [➡️]`;
   - last: строка 1 `[⬅️] [✅ Finish]`, строка 2 `[🏠]`;
   - single: строка 1 `[✅ Finish]`, строка 2 `[🏠]`.
22. Completion Level 4:
   - при наличии Level 5 есть `5️⃣ Level 5`;
   - есть `🔄 Заново / 🔄 Take again`;
   - есть `🎙 Уровни / 🎙 Levels` + `🏠`.
23. Completion Level 5:
   - есть `🔄 Заново / 🔄 Take again`;
   - есть `🎙 Уровни / 🎙 Levels` + `🏠`.
24. Повторный вход в уровень:
    - started but not completed -> текст `Вы уже начали... / You have already started...`;
    - completed -> текст `Вы уже завершили... / You have already completed...`.
25. Кнопки `Start over / Continue` на started-экране entry:
   - строка 1: `🔄 Сначала / 🔄 Start over` + `▶️ Continue`;
   - строка 2: `⬅️` + `🏠`.
26. Кнопки completed re-entry:
   - строка 1: `⬅️` + `🔄 Заново / 🔄 Take again`;
   - строка 2: `🏠`.
27. Progress main menu обновляется по факту completed вопросов:
    - `questions_total` = число активных `exam_questions`;
    - `questions_completed` = completed для пользователя.
28. Settings -> reset progress:
    - `🎙 Questions` очищает `exam_question_progress`, runtime `exam_question_state` и `temporary_messages` для Questions audio;
    - `⚠️ All progress` тоже очищает Questions progress/state + temporary audio records;
    - при runtime reset бот пытается best-effort удалить аудио-сообщения из Telegram, но ошибки удаления не ломают flow.
29. Stale callbacks/контент:
    - недоступный уровень -> alert + возврат к списку уровней/empty;
    - удалённый текущий вопрос -> alert + возврат к уровням/empty;
    - неизвестный `questions:view` mode не вызывает traceback (безопасно открывается base view);
    - если отдельный review-блок исчез из контента, экран остаётся рабочим и просто не показывает пустой блок.
30. EN quick check: основные экраны/кнопки (`levels`, entry screens, question views, completion) локализованы.
31. Clean-chat и one-main-message сохраняются:
    - основной flow работает через одно main UI-сообщение;
    - в чате максимум main UI + текущее временное аудио Questions.

## Проверка справки об экзамене

Что проверить:
1. В главном меню всегда видна кнопка `ℹ️ Как проходит экзамен / ℹ️ How the exam works`.
2. Нажатие на кнопку открывает экран обзора экзамена в основном UI-сообщении.
3. На экране обзора кнопка `🎙 ...` открывает экран интервью.
4. На экране интервью кнопка `🛫 ...` открывает экран ролевой игры.

## Проверка clean chat guard

Основное правило:
- любое входящее сообщение пользователя в private chat удаляется после обработки, если Telegram позволяет.
- для message input-сценариев (`location`, ручной ввод времени) Telegram не поддерживает `callback toast`,
  поэтому бот **не отправляет отдельные подтверждающие сообщения в чат**, а сразу обновляет основное UI-сообщение.
- source of truth: runtime-guard `features/clean_chat/handlers.py`.

Что проверить:
1. Отправьте обычный текст вне состояния ожидания:
   - сообщение удаляется;
   - отдельный ответ "неизвестная команда/сообщение" не отправляется.
2. Отправьте неизвестную команду, например `/abc`:
   - сообщение удаляется;
   - чат не засоряется лишними ответами.
3. В состоянии "другое время" отправьте `19:30`:
   - значение обрабатывается;
   - сообщение пользователя удаляется.
4. В состоянии "другое время" отправьте некорректный формат:
   - показывается предупреждение текущего экрана;
   - сообщение пользователя удаляется.
5. В шаге автоопределения часового пояса отправьте геолокацию:
   - timezone определяется/обрабатывается;
   - ReplyKeyboard скрывается;
   - сообщение пользователя с геолокацией удаляется.
   - отдельное подтверждение "таймзона установлена" в чат не отправляется.
6. В шаге "другое время" (советы/напоминания) отправьте корректный `HH:MM`:
   - значение сохраняется;
   - сообщение пользователя удаляется;
   - отдельные подтверждения "время установлено" в чат не отправляются;
   - сразу открывается следующий экран с уже выбранным значением в основном UI.

Что проверить:

   - после успешной валидации очищает `exam_questions`, `exam_question_progress`, `exam_question_state`;

## Routes smoke checks (v1.0)

Локальные env для Routes smoke:

- `DB_PATH=data/local/dev_main.db`

Что проверить:

1. Routes list:
   - при выполнении условий из блока Main menu кнопка `🛫 Routes` видна;
   - нажатие открывает `Routes list` с пагинацией/навигацией.
2. Briefing:
   - выбор маршрута открывает `Briefing`;
   - в briefing доступны входы в `Start`, `News`, `Questions`.
3. Full flow:
   - `Routes list -> Briefing -> Start -> Scenario steps -> random News -> random Question Block -> Finish`;
   - в full mode прогресс маршрута засчитывается только на `Finish`;
   - в full mode нет кнопки возврата `⬅️ К маршруту`.
4. Free news flow:
   - `Briefing -> News list -> selected News -> Question block list -> Questions -> Finish`;
   - в free mode прогресс маршрута не засчитывается;
   - в free mode есть возврат `⬅️ К маршруту`.
5. Free questions flow:
   - `Briefing -> Question block list -> Questions -> Finish`;
   - в free mode прогресс маршрута не засчитывается;
   - в free mode есть возврат `⬅️ К маршруту`.
6. Interrupt:
   - full mode: нажатие `Main menu` открывает interrupt confirmation (`остаться / выйти`);
   - free mode: `Main menu` возвращает напрямую без interrupt confirm.
7. Media order:
   - порядок отображения: `image -> audio -> text/buttons`;
   - runtime audio для routes отправляется только через `media_assets/file_id`;
   - runtime images работают в режиме cache-first через `media_assets/file_id` с local fallback.
8. Clean chat:
   - в routes-flow пользовательские сообщения удаляются clean-chat guard-слоем best-effort;
   - временные route media-сообщения очищаются при навигации между экранами.

## Если нет `BOT_TOKEN`

- `python scripts/smoke_check.py` может показать предупреждение про отсутствие токена — это ожидаемо для частичной проверки.
- `python run.py` без `BOT_TOKEN` не должен использоваться для полного запуска.

Рекомендуемое действие:
1. Добавить `BOT_TOKEN` в `.env`.
2. Повторить `python scripts/smoke_check.py`.
3. Повторить `python run.py`.
